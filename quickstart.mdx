title: "Quickstart"
description: "From a new Pincast account to a working app on a test key, then on to the review queue."
---

You'll make an account, start a small card app on its own test key, record a test collect, claim the app and ask Pincast to review it. Until the last step, everything you write is test data, kept apart from anything public.

## What you need

- Node 20.12 or later, and `curl`.
- A browser, for your Pincast account and the dashboard.

## 1. Make your account

Open the [developer dashboard](https://pincast.fm/developers/dashboard). If you're signed out, it sends you to the sign-in page, where you can create an account.

Signing in brings you back to the dashboard. It reads **No apps yet**. Your app appears here in step 4.

## 2. Make your app with one command

```bash
npm create pincast my-app
```

The folder has to be new or empty. The command needs no account, and it does five things:

1. Copies a small starter app, Lantern Walk, into `my-app`.
2. Asks Pincast for one test app.
3. Writes the app's test key to `.env`, along with the test person `test_demo` and your claim link. Only your account can read that file, and git ignores it.
4. Puts the new app's id in `shared/app.js`.
5. Sends the starter's set and one test collect, so the app has a real card to show.

It never prints the key. It does print the link that claims the app:

```text wrap
Your app is ready in my-app, with the test app test-k3f7x2m4qa.

Its key is saved in my-app/.env. Only your account can read that file, and git ignores it.

Pincast has your set, and the test person test_demo holds Ferry Steps.

To keep this app past 2026-11-29, open this link while signed in to Pincast:

  https://pincast.fm/developers/claim#code=pcc_...
```

A test app ends after 7 days unless you claim it. If you lose the link, it's in `.env` as `PINCAST_CLAIM_URL`.

`npx @pincast/cli init my-app` runs the same code through the [`pincast` command](/guides/pincast-command), which also sends sets and collects from your terminal.

## 3. Open your first card

The command registered the set's eight cards and recorded that the test person `test_demo` collected Ferry Steps. Install the app and start it:

```bash
cd my-app
npm ci
npm run dev
```

Open http://localhost:5173. The line at the top reads **Live from the Pincast API.** Ferry Steps is on the table, and the other seven cards are under the Missing chip.

### If the command printed `curl` commands

Your app is still made when the set or the collect doesn't go through. The command names the one Pincast didn't confirm and prints what's left to send. Run what it printed, from the folder where you ran it. Until the set arrives, the page shows this line in place of cards:

```text wrap
Set old-town-lanterns isn't registered for this app yet. Send it with PUT /v1/sets/old-town-lanterns first.
```

With both left to send, the commands are:

```bash
cd my-app
npm ci
set -a; . ./.env; set +a
curl -X PUT https://api.pincast.fm/v1/sets/old-town-lanterns \
  -H "X-Pincast-Key: $PINCAST_KEY" \
  -H "Content-Type: application/json" \
  -d @data/set.json
curl -X POST https://api.pincast.fm/v1/sets/old-town-lanterns/collects \
  -H "X-Pincast-Key: $PINCAST_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "card": "lantern:ferry-steps", "actor": { "id": "test_demo", "source": "anonymous" } }'
npm run dev
```

You can send the `PUT` again at any time. Send this `POST` once: with no `at` in its body, each run counts as another collect.

If only the collect is left, the command prints the `POST` alone with an `Idempotency-Key` line. That line makes a repeat safe for 24 hours, even if the first try reached Pincast and its answer got lost.

### Or send them from Node

The [typed package](/guides/typed-package), `@pincast/api`, makes the same two calls from your own code. It puts an `Idempotency-Key` on each, so a retry it makes on its own can't count twice. In the app's folder, add the package and a short script:

```bash
npm install @pincast/api
```

```js send-first.mjs
import { readFileSync } from 'node:fs'
import { Pincast, testActor } from '@pincast/api'

const pincast = new Pincast()
await pincast.putSet('old-town-lanterns', JSON.parse(readFileSync('data/set.json', 'utf8')))
await pincast.postCollect('old-town-lanterns', { card: 'lantern:ferry-steps', actor: testActor('demo') })
```

Load `.env`, then run the script once. Like the `POST` above, its collect has no `at`, so each run counts as another collect.

```bash
set -a; . ./.env; set +a
node send-first.mjs
```

## 4. Claim your app

Open your claim link in a browser and tap **Claim this app**. If you're signed out, the page offers **Sign in to claim** and brings you back afterward.

Your app opens on the dashboard. The claim changes three things:

- The app and its key stop expiring, so your `.env` keeps working.
- The app's room grows from 3 sets, 200 cards and 1,000 collects to 20 sets, 2,000 cards and 20,000 collects.
- You can take it live.

A claim link works once, and it ends when its test app does. One account holds up to 10 apps.

## 5. Manage your test keys

Open your app's **Keys** tab. Under **Test keys** is the key the command made, named by its last four characters. Pincast stores only a hash of a key, so your `.env` holds the one whole copy.

- **Make a test key** makes a second key and shows it once. Tap **Copy key**, store it, then tap **I saved this key**. An app holds two working test keys at most.
- **Replace** gives you a new key, shown once, and keeps the old one working for 7 days.
- **Revoke** stops a key from its next call.

The key from the command takes 60 calls a minute, and so does a key that replaces it. A key you make with **Make a test key** takes 600.

To switch keys, change `PINCAST_KEY` in `.env`, load the file again and restart the app. The reload matters, because a value already in your shell wins over the file:

```bash
set -a; . ./.env; set +a
npm run dev
```

## 6. Go live

A live app is a second app with its own id and its own key. Your test app, test key and test data stay as they are, and nothing copies across.

On your app's **Go live** tab:

1. Enter a **Live id**: 1 to 32 lowercase letters, digits and hyphens, starting and ending with a letter or digit. It becomes part of your live key and can't change. It can't start with `test-`, and a few ids are reserved.
2. Enter a **Contact email**, where Pincast writes about your review.
3. Open the **Pincast developer terms**, read them, and tick the box to accept them. Pincast records who accepted, for which app, which version and when. If you're building for a company, you accept for it too.
4. Tap **Go live and ask for review**.
5. Your live key appears once. Tap **Copy key**, store it, then tap **I saved this key**.

The tab now reads **Waiting for review**.

If the tab says **Go live isn't open yet**, the terms aren't ready and no app can go live. Your test app and test key keep working. If it says **The developer terms have changed**, read the new version and tick the box again.

### Move the starter to your live key

A live key writes real data, and no API call deletes it. Your test set doesn't carry over, so send the set again:

1. In `shared/app.js`, change `APP.id` to your live id.
2. In `.env`, set `PINCAST_KEY` to your live key and `PINCAST_ACTOR` to `guest-lantern-1`, a guest id.
3. Write the starter's test snapshots again, because they carry the app id:

   ```bash
   UPDATE_GOLDENS=1 npm test
   ```

4. Send the set and one guest collect with the live key:

   ```bash
   set -a; . ./.env; set +a
   curl -X PUT https://api.pincast.fm/v1/sets/old-town-lanterns \
     -H "X-Pincast-Key: $PINCAST_KEY" \
     -H "Content-Type: application/json" \
     -d @data/set.json
   curl -X POST https://api.pincast.fm/v1/sets/old-town-lanterns/collects \
     -H "X-Pincast-Key: $PINCAST_KEY" \
     -H "Content-Type: application/json" \
     -d '{ "card": "lantern:ferry-steps", "actor": { "id": "guest-lantern-1", "source": "anonymous" } }'
   ```

5. Restart `npm run dev`. The page shows that guest's card, read through your live key.

## Where your app stands

Your app is in Pincast's review queue. Its live key works now, and its sets stay off the directory and Placecard until the review passes.

The result shows on the app's **Overview** tab:

- **Listed**: people can find your app in the Pincast directory.
- **Review declined**: the reviewer's note appears there. Your live key keeps working. Make the changes, then tap **Ask for review again** on the **Go live** tab.

[Appear in the directory and in Placecard](/guides/directory-and-placecard) lists what the review looks at.

## Start from the dashboard instead

You can make a test app without the command. On the dashboard, tap **New app**, enter an **App name** and tap **Make app**. The app is yours from the start, so it has no claim step and no end date. Open its **Keys** tab and tap **Make a test key**.

To run the starter on that key:

1. Run `npm create pincast my-app`, then `cd my-app` and `npm ci`. The command makes a test app of its own, which you can ignore: it ends after 7 days.
2. Put your key in `PINCAST_KEY` in `.env`.
3. Change `APP.id` in `shared/app.js` to your app's id, which starts `test-`.
4. Run `UPDATE_GOLDENS=1 npm test`, then the `set -a`, `curl` and `npm run dev` lines from step 3.

## When something goes wrong

| What you see | What to do |
| :- | :- |
| `Set old-town-lanterns isn't registered for this app yet.` | Run the `PUT` in step 3 with this app's key. |
| `This key is for the app ...` | `APP.id` in `shared/app.js` doesn't match the key. Change it to the part of your key between `pck_` and the next underscore. |
| `Pincast has made all the test apps it makes in a day.` | The message says when to try again. |
| `Too many test apps have come from this network.` | The message says when to try again. |
| `... already has files in it` | Name a new or empty folder. |
| 403 `test_person_required` | A test key's call named someone whose id doesn't start `test_`. Use `test_demo`. |
| 409 `test_limit_reached` | The test app is full. Claim it, or take it live, for more room. |
| **This claim link no longer works** | A code works once and ends with its test app. If you claimed the app already, it's on your dashboard. |

[Errors](/api-reference/errors) lists every API code.
